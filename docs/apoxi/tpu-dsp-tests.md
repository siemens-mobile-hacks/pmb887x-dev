# TPU/DSP Baseband tests

These tests are needed to replace the approximate QEMU Baseband model with
measured PMB887x behavior. Run the hardware tests separately on PMB8875 and
PMB8876 and always print the CPU revision and DSP Mask ID.

## Documented behavior used by QEMU

- TPU decoder values `1..9`, `15`, `17`, and `18` control the documented GSM
  signals.
- Decoder value `5` clears `EQON`, `MONON`, `SCON`, and `FCON` together.
- `FRAME` is generated by decoder value `15`.
- Baseband RAM starts at the CPU metadata `DEMODULATOR_RAM` address.
- The circular sample area is `0x3C0` words; `0x3C0..0x3FF` contains
  coefficients.
- A rising `EQON`, `MONON`, `SCON`, or `FCON` starts a Baseband job and resets
  `BB_WR_POINTER`. `RXON` does not reset it.
- `BB_WR_POINTER` advances while samples are written and retains the final
  address after the job ends.
- One monitoring window advances `BB_WR_POINTER` by 256 words, corresponding to
  64 symbols and four I/Q words per symbol.
- The RF-less input consists of zero I/Q samples.
- Any rising `EQON`, `MONON`, `SCON`, or `FCON` edge sets `INT_FINTA0.BBHI`.
- Any falling edge sets `INT_FINTA0.BBLO`. `RXON` changes only `BB_STATUS`.
- Crossing `BB_INT_POINTER` sets `INT_FINTA0.BB_FULL`.

The fixed 64-symbol RF-less input and exact interrupt-edge behavior remain QEMU
approximations and need hardware measurements.

## TPU decoder and signal tests

Create a Timer RAM program with one event for each decoder value and record the
DSP-visible state after every event.

1. Verify the set events for `EQON`, `MONON`, `SCON`, and `FCON`.
2. Verify whether value `5` clears all four signals simultaneously.
3. Verify the independent `RXON` and `TXON` set/clear events.
4. Verify the `CODON` set/clear events.
5. Determine whether decoder values `10..16` generate pulses, toggle levels, or
   only set interrupt requests. In particular, confirm that value `15` is
   `FRAME`.
6. Repeat an event while its decoder value is already active and check whether
   another edge or interrupt is generated.
7. Check signal state across TPU stop/start, TPU reset, DSP reset, and frame
   wrap.

Log the Timer RAM event address, TPU counter, complete trigger word,
`BB_STATUS`, and all `INT_FINTA0` bits for each step.

## Baseband register tests

For every Baseband register, record the reset value and the result of writing
`0x0000`, `0xFFFF`, walking ones, and walking zeroes.

- `BB_CTRL`
- `BB_INT_POINTER`
- `BB_WR_POINTER`
- `BB_STATUS`
- `BB_DCOFFSET_I` and `BB_DCOFFSET_Q`
- `BB_FSHIFT`
- `BB_BRFILTER_CTRL`
- `BB_PBASE_MSB/LSB`
- `BB_PADJ_MSB/LSB`
- `BB_IQ_IMBALANCE`

The test must identify read-only bits, writable masks, reserved-bit readback,
and whether `BB_STOP` or `BB_ON` changes hardware-controlled signal handling.

## Baseband interrupt tests

Enable one DSP interrupt bit at a time and test both the flag register and the
actual DSP interrupt vector.

1. Generate rising and falling edges for each of `EQON`, `MONON`, `SCON`, and
   `FCON`; determine the exact `BBHI` and `BBLO` edge mapping.
2. Change `RXON` and verify whether it can generate either interrupt.
3. Generate several edges before clearing the flag and determine whether flags
   latch, count, or coalesce.
4. Clear `BBHI` and `BBLO` while the corresponding input remains active and
   check whether they immediately reassert.
5. Verify that disabling an interrupt masks the DSP line without preventing the
   flag from latching.
6. Measure the delay from the TPU event to the first instruction of the DSP
   interrupt handler.
7. Verify `FRAME`, `CODONHI`, and `CODONLO` independently from Baseband edges.

## Baseband RAM and pointer tests

Fill the complete demodulator RAM with a nonzero pattern before starting a
receive window, then inspect it after the window.

1. Determine the first and last address written by Baseband.
2. Determine the I/Q word order and signed sample width.
3. Measure `BB_WR_POINTER` advancement for window lengths from 7 through 190
   symbols.
4. Determine the number of RAM words written per symbol and whether decimation
   changes it.
5. Verify the pointer modulus: `0x3C0`, `0x400`, or another value.
6. Start close to the end of the buffer and verify wraparound.
7. Place `BB_INT_POINTER` before, at, and after the current write pointer and
   determine the exact `BB_FULL` comparison and edge behavior.
8. Repeat with `BB_STOP`, `BB_ON`, `BB_ADCMODE`, and `BBADAP_EN` combinations.
9. Repeat without an RF input and record the actual RAM contents, Pbase, and
   Padj values.

## Firmware-level monitoring test

Use the normal Mask ROM plus phone user firmware; do not replace the monitoring
handler with a custom implementation.

1. Initialize `SM_MON_INDEX` and all eight result slots with unique sentinels.
2. Schedule one valid `MONON` window through TPU Timer RAM.
3. Record `BB_WR_POINTER`, Baseband RAM, `INT_FINTA0`, DSP PC at interrupt entry,
   and the Shared RAM result.
4. Confirm that zero I/Q produces `0xFF80`.
5. Confirm that the index advances modulo eight and only the selected slot is
   changed.
6. Test invalid indices below zero and above seven.
7. Run more than eight windows to verify ring wraparound.
8. Test the documented minimum, useful minimum, and maximum window lengths, and
   gaps immediately below and above 70 microseconds.

The emulator integration test passes when the SL98 firmware repeatedly
replaces consumed `0xFFFF` slots and `l1mon` no longer raises assertion
`0x4011`.

## QEMU regression tests

After applying hardware results, add native unit coverage for the TPU decoder,
Baseband register masks, status transitions, pointer wrap, and interrupt flags.
Then run the existing DSP core/peripheral tests and the BSP DSP functional
suite for PMB8875 and PMB8876 before testing a complete SL98 boot.
